# 학습 진도 덮어쓰기 수정 — 2026-11-16

## 신고와 확인 범위

사용자가 일본어를 3장까지 공부한 뒤 다음 날 기록이 초기화됐다고 신고했다. 현재 앱은 같은 origin의 브라우저 IndexedDB `study-library`에 읽던 위치·읽음·복습·메모·북마크를 저장한다. 문제의 선택 답과 점수는 기존 요구에 따라 재진입 시 초기화한다. 매일 데이터를 삭제하는 일정 처리는 코드에서 발견되지 않았다.

실제 사용 기기·브라우저·주소 및 소실된 항목에 대한 확인은 대기 중이다. 아래 덮어쓰기는 격리된 테스트 브라우저에서 확인한 결함이며, 사용자 기기에서 일어난 소실 경로의 확정에는 해당 환경 확인이 필요하다.

## 재현한 결함

1. 첫 탭에서 `nominal`을 읽음으로 표시한다.
2. 다른 탭에서 `wa-ga`, `location`을 읽음으로 표시한다. DB에는 세 페이지가 저장된다.
3. 첫 탭에서 스크롤한다. 250ms 뒤 자동 저장이 실행된다.
4. 수정 전 DB의 `readPages`가 `[nominal, wa-ga, location]`에서 `[nominal]`로 줄었다.

첫 탭의 메모리에 남은 전체 Progress 객체가 최신 시각을 붙여 저장됐기 때문이다. 기존 저장 함수의 시각 비교는 그 객체를 최신으로 판단했고, 다른 탭에서 추가된 읽음·복습 배열까지 교체했다. 페이지 종료의 마지막 위치 저장도 같은 함수를 사용했다.

## 수정

- `src/lib/storage.ts`의 읽기 위치 저장은 같은 IndexedDB readwrite 트랜잭션에서 현재 읽음·복습 배열을 유지한다.
- 읽음·복습 버튼은 그 트랜잭션의 최신 배열에 현재 페이지의 추가 또는 해제를 반영한다. 다른 페이지와 다른 표시 종류를 함께 보존한다.
- 가져오기의 기존 최신 시각 기반 병합과 JSON 형식은 유지한다.
- `src/components/Reader.tsx`의 스크롤·종료 저장에 위치 저장 의도를 지정하고 버튼 저장에는 해당 표시 변경을 지정했다.
- 페이지 이동 직후 읽음 버튼을 눌러도 현재 페이지 ID를 저장한다. 늦게 도착한 초기 조회가 방금 저장한 UI 상태를 이전 값으로 되돌리지 않도록 했다.
- 읽음·복습 표시는 트랜잭션이 완료된 뒤 화면에 확정한다. 저장 대기 중에는 상태 문구를 표시한다.
- 저장에는 기존 `study-library` v1 스키마와 학습 ID를 사용한다.

## 검증

- 수정 전 Chromium Desktop 회귀 테스트에서 세 페이지가 한 페이지로 줄어드는 실패를 확인했다.
- 수정 후 같은 Desktop 재현 테스트가 통과했다.
- `tests/browser/progress.spec.ts`에서 이전 탭 스크롤·탐색, 다른 탭의 표시 추가·해제·복습 보존, 빠른 장 이동의 현재 페이지 ID, 시스템 시각을 하루 진행한 뒤 새로고침과 현황 표시를 검사한다.
- 최초 전체 검사에서 95/96이 통과했다. 철학 WebKit 모바일 테스트 1건은 읽음 저장 완료 전에 새로고침해 실패했다. 저장 완료 대기를 추가하고 실제 UI 표시도 커밋 완료 시점에 확정하도록 보완했다.
- 최종 전체 브라우저 검사 96/96 통과. Chromium·WebKit 각각 PC/모바일 프로필에서 검사했다. 신규 진도 회귀 검사 12개가 포함된다.
- 단위 검사 21/21, 타입 검사, 콘텐츠 2권 검증, `/study-automation/` 경로의 Pages 빌드 통과.
- 공개 사이트 반영과 실제 HTTPS 회귀 검사는 배포 후 확인한다.

## 복구와 실제 기기 확인

현재 서버에는 개인 학습 기록의 사본이 없고 IndexedDB에는 변경 이력이 없다. 이미 덮인 배열의 복원 여부는 기존 내보내기 파일과 다른 브라우저·기기의 남은 기록을 확인해야 판단할 수 있다. 이 작업에서 사용자 브라우저의 기록을 수정하거나 임의로 복원하지 않았다.

기존 탭은 이전 JavaScript를 계속 실행할 수 있으므로 배포 후 사용하던 학습 탭들을 일반 새로고침해 새 버전을 받아야 한다. 실제 iPhone의 보존 결과와 브라우저 저장 공간 삭제·비공개 모드 여부는 별도 확인이 필요하다. 하루 진행 검사는 브라우저 시각 변경을 사용하며 실제 하루 대기나 iPhone의 저장소 회수 동작을 검증한 결과로 해석하지 않는다.
