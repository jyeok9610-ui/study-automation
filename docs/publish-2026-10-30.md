# 공개 배포·WebKit 검증 — 2026-10-30

사용자가 직전 보고의 ‘공개 배포와 실제 iPhone/Safari 검증’도 진행하라고 승인했다. iPhone에서 직접 확인 가능하다는 답변도 받았다. 추가 확인을 반복 요구하지 않고 기존 jyeok9610-ui/study-automation master와 GitHub Pages 워크플로로 배포한다.

## 검사 환경과 수정

- 기존 Playwright 1.64.1에 공식 WebKit 27.2(v2370) 브라우저 바이너리만 설치했다. 앱의 npm 의존성/잠금 파일·외부 서비스·사용자 학습 기록은 변경하지 않았다.
- Chromium PC/모바일과 WebKit Desktop Safari/iPhone 13 프로필을 추가했다. Windows WebKit 엔진 검사이며 실제 Apple 기기의 Safari라고 보고하지 않는다.
- WebKit에서 사전 패널을 닫으면 초점이 원래 버튼으로 돌아오지 않는 문제를 발견했다. WebKit 포인터 클릭은 document.activeElement를 body에 둘 수 있으므로, 사전·출처·메모 공통 helper가 실제 클릭한 event.currentTarget을 기억하게 수정했다. Escape/닫기 뒤 초점 복원 검사를 통과했다.
- 터치 WebKit에서 전역 사용자 정의 스크롤바가 8px의 실제 가로 이동을 만들었다. 스크롤바 스타일을 fine pointer/hover 환경에만 적용해 터치는 브라우저 기본 표시를 사용한다. 문서를 가로로 이동시켜 확인하는 검사도 추가했다. 단순 scrollWidth 비교만으로 성공 판정하지 않는다.
- 시각 QA가 읽음 표시를 누른 뒤 저장 완료를 기다리지 않고 전체 페이지로 이동하던 경합도 수정했다. 앱의 저장 성공 메시지를 기다린 뒤 이동한다.

## 검증·증거

- Chromium·WebKit PC/모바일 4개 프로필의 40개 E2E. 기존 북마크/백업/진도/메모 보존, 탐색, 검색, 노선/지도, 세 학습 활동, Light 고정/모션 감소, 포커스 복원과 터치 가로 이동을 확인한다.
- `.impeccable/review/liquid-glass/webkit-release/`: 1920×1080, 1440×900, 390×844 WebKit 캡처/수치. 원자료나 사용자 브라우저 기록이 아닌 격리된 QA 컨텍스트를 사용한다.
- TypeScript 검사와 Pages base 빌드. 실제 배포 CI에서 단위/통합 검사와 콘텐츠 검사도 수행한다.
- 검토한 커밋의 정확한 파일만 업로드하며 data/·DB·원자료 스냅샷·로그·node_modules·로컬 검수 이미지를 올리지 않는다. 일반 자격증명 패턴 검색에서 일치 파일 없음.

## 배포 절차와 실기기 확인

기존 공개 주소: https://jyeok9610-ui.github.io/study-automation/

승인된 master를 정상 push하고 GitHub Actions 성공과 실제 HTTPS의 새 홈/책/북마크를 확인한다. 실행 ID·커밋·성공 결과는 프로젝트의 Obsidian 배포 기록에 남긴다. 원자료/DB/제작실/환경 파일이 정적 사이트에 노출되지 않는지도 확인한다.

실제 iPhone이 PC에 연결되어 있지 않아 자동 조작하지 못한다. 사용자가 공개 주소를 Safari로 열어 화면/스크롤·북마크 보존·문제 초기화·읽기 기록 보존을 확인하도록 안내한다. Wi-Fi/셀룰러 여부와 실제 답변을 구분해 기록한다. 미응답을 실기기 성공으로 간주하지 않는다.

## 사전 검사 완료

Chromium·WebKit PC/모바일 E2E 40/40 통과. WebKit 39 화면/기기 조합의 실제 가로 이동 최댓값0px, 넘침0, 런타임/요청 오류0. 60장 캡처를 보존했다. TypeScript·Pages base 빌드 통과. 단위/콘텐츠 검사는 실제 배포 CI에서도 확인한다.
